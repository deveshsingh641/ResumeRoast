## 1. Traffic-Spike Readiness & Scaling

Viral traffic spikes (e.g., a trending post on X, LinkedIn, or Reddit) can drive thousands of visitors within an hour. Here is the operational setup to ensure stability.

### 1.1 Database Connection Pooling
- **Implementation**: The backend uses `psycopg2.pool.ThreadedConnectionPool` inside `backend/app/db/database.py`.
- **Environment Tuning**:
  ```ini
  DB_POOL_MIN=2
  DB_POOL_MAX=20
  ```
- **Why it matters**: Remote PostgreSQL connections (Supabase/Neon) require 80–200ms TLS handshakes if unpooled. Connection pooling ensures connection reuse, keeps queries sub-millisecond, and prevents exhausting database connection limits during traffic spikes.

### 1.2 AI Provider Rate Limits & Graceful Degradation
- **Primary AI Engine**: Google Gemini 1.5 Flash (Rate limit: 15 RPM / 1,500 RPD on free tier; 1,000+ RPM on paid pay-as-you-go tier).
- **Secondary Fallback**: Groq (Llama 3.3 70B) & Anthropic Claude 3.5 Sonnet.
- **Failover Engine**: If external APIs return `429 Too Many Requests` or time out, `ai_analyzer.py` automatically falls back to the internal heuristic generator. Users receive an immediate, high-quality, grounded critique rather than an unhandled 500 error.

### 1.3 Running Load Tests
Benchmark the backend before posting major announcements:
```bash
# Test with 5 concurrent workers firing 20 requests
python backend/scripts/load_test.py --concurrency 5 --requests 20 --url http://localhost:8000

# Aggressive burst benchmark (10 workers, 50 requests)
python backend/scripts/load_test.py --concurrency 10 --requests 50
```
- **Acceptable baseline**: p50 latency < 3500ms (with live LLM call); p95 < 6500ms; 0 unhandled 500 errors.

### 1.4 "Brace for Impact" Runbook (Viral Traffic Checklist)
When launching a campaign or noticing sudden incoming traffic:
1. **Check Backend Status**: Visit `https://your-backend.onrender.com/health` to ensure healthy DB and model readiness.
2. **Check Founder Metrics**: Visit `https://your-backend.onrender.com/api/admin/metrics` to inspect active visitor concurrency and roasts generated today.
3. **Bump Web Concurrency (Render/Railway)**:
   - In Render: Dashboard → Settings → Scale → Switch plan from Starter to Standard (or set instance count to 2–3).
   - In Railway: Increase RAM limit from 512MB to 2GB.
4. **Monitor Gemini Quota**: Check Google Cloud / AI Studio Dashboard for remaining daily quota.

## 2. Cost & Abuse Monitoring

Every roast incurs compute and optional LLM API costs. Proactive tracking prevents surprise bills.

### 2.1 Unit Economics per Roast
| Provider / Service | Typical Tokens | Cost per Roast (USD) | Cost per 1,000 Roasts |
| :--- | :--- | :--- | :--- |
| **Google Gemini 1.5 Flash** | 3.5k input / 800 output | **$0.0003** | **$0.30** |
| **Anthropic Claude 3.5 Sonnet** | 3.5k input / 800 output | **$0.0240** | **$24.00** |
| **Heuristic Fallback Engine** | Local Python compute | **$0.0000** | **$0.00** |
| **Edge TTS / Voice Cache** | Edge cached mp3 | **$0.0000** | **$0.00** |

*Key takeaway*: Running on Gemini 1.5 Flash keeps 10,000 roasts at approximately **$3.00 USD total**.

### 2.2 Budget Alerts Setup
1. **Google AI Studio / Google Cloud**:
   - Navigate to Google Cloud Console → Billing → Budgets & Alerts.
   - Set a monthly budget of **$25 USD** with alert thresholds at 50%, 80%, and 100%.
2. **Anthropic API Console** (if enabled as fallback):
   - Navigate to Console → Settings → Limits & Spend.
   - Set monthly hard limit to **$50 USD**.

### 2.3 Abuse Prevention
- **Per-IP Rate Limiting**: Managed via `slowapi` and device fingerprint hashes in `backend/app/routers/roast.py`. Free users are restricted to `FREE_TIER_DAILY_LIMIT=1` per day.
- **Debounce / Dedup Protection**: Submitting the exact same resume file within a 60-second window returns the cached result immediately from memory without firing duplicate AI calls.

## 4. Customer Support & Manual Overrides

Paying customers experiencing checkout or webhook delays must be unblocked immediately.

### 4.1 Support Channels & SLA
- **Customer Email**: `support@resumeroast.app`
- **Privacy & Deletion Requests**: `privacy@resumeroast.app`
- **SLA**:
  - Pro / Payment Issues: **Under 4 hours** response time.
  - Free tier feedback: Reviewed daily.

### 4.2 Instant Pro Manual Override Tool
If a customer pays via UPI/Cards and their webhook failed:
#### Option A: Terminal CLI Script
```bash
# Run directly on server or local terminal
python backend/scripts/manual_pro_override.py customer@example.com --action grant --reason "Paid via Razorpay ref #12345"

# Check customer status
python backend/scripts/manual_pro_override.py customer@example.com --action check

# Revoke if refunded
python backend/scripts/manual_pro_override.py customer@example.com --action revoke
```

#### Option B: Authenticated Admin API Endpoint
```bash
curl -X POST "https://your-backend.onrender.com/api/admin/user/override-pro" \
  -H "Content-Type: application/json" \
  -H "X-Admin-Key: your_configured_admin_secret" \
  -d '{"email": "customer@example.com", "action": "grant_pro", "reason": "Customer support resolution"}'
```

## 5. Database Backups & Disaster Recovery

### 5.1 Supabase Automated Backups
- **Automated Backups**: Enabled by default on Supabase (Daily backup retained for 7 days on Pro plans).
- **Point-in-Time Recovery (PITR)**: Allows rolling back to any specific minute in the past 7 days if data corruption occurs.

### 5.2 Off-Site JSON/Database Exporter
For an independent, offline safety archive:
```bash
# Export all tables (users, roasts, pro_waitlist, battles, wall_entries)
python backend/scripts/export_backup.py
```
- Backups are stored in `backend/storage/backups/resumeroast_backup_YYYYMMDD_HHMMSS.json`.
- Automatically ignored by `.gitignore` to prevent secret leaks.

## 6. Founder Metrics & Daily Monitoring Routine

Check these numbers once daily during launch weeks to catch issues early.

### 6.1 Founder Metrics Endpoint
```bash
# Fetch complete JSON metrics
curl -s "https://your-backend.onrender.com/api/admin/metrics" \
  -H "X-Admin-Key: your_admin_secret"
```

### 6.2 Key Metrics Checklist
1. **Total Roasts Attempted vs Completed**: Check `summary.total_roasts_all_time` and `traffic_7d`.
2. **Waitlist Signups**: Check `summary.waitlist_signups` to gauge pre-launch audience demand.
3. **Pro Conversions**: Check `summary.pro_subscribers` and `summary.estimated_mrr_inr`.
4. **AI Spend**: Check `costs.estimated_total_ai_spend_usd` to verify costs remain below $5/month.
5. **Infrastructure Health**: Verify `infrastructure.is_pooled: true`.
